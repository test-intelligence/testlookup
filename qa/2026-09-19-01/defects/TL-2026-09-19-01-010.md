# TL-2026-09-19-01-010 — `/policies` identifies each project by a truncated UUID

- Found by: JR-06 (surfaces), observed in the live UI
- Severity: **S3** (usability on the release-gate policy surface) · Priority: P3
- Component: `frontend/src/pages/PolicyEditorPage.tsx:257`
- Status: **REPORTED**, not fixed

## Observed

`http://testlookup.local/policies`, admin, three policies:

```
qa-probe-policy-1            v1  Draft    Project: d4a8d31f... · Created: 9/9/2026
Gate Probe Policy            v1  Active   Project: 647c2ee4... · Created: 8/15/2026
ZZ probe policy - delete me  v1  Draft    Project: 9af8eb8f... · Created: 8/9/2026
```

Every policy names its project as the first eight hex characters of a UUID. The
list is not filtered by the active project, so these are three *different*
projects, distinguishable only by comparing `d4a8d31f` / `647c2ee4` / `9af8eb8f`.

A policy author cannot tell which project a gate policy governs without copying
a fragment of an id and looking it up elsewhere. On a surface whose whole job is
"which thresholds apply to which project", that is the one fact the row has to
carry.

## Cause

```tsx
// PolicyEditorPage.tsx:257
{p.project_id ? `Project: ${p.project_id.slice(0, 8)}...` : 'System Default'}
```

A hard truncation of the raw identifier. The page never imports
`useProjectStore`, so it has no access to the names — although the store holds
them and the rest of the app uses them freely.

## This is an inconsistency, not a data limitation

`/releases`, measured in the same session, renders the same relationship
correctly — "Inventory Service", "Auth Service", "Checkout Service", each with
an avatar chip. The names are available client-side. `/policies` is the surface
that does not use them.

The `'System Default'` branch is right and worth keeping: a null `project_id`
genuinely means the system-wide policy.

## Suggested fix

Resolve the name from `useProjectStore` and fall back to the truncated id only
when the lookup misses (a policy for a project the user cannot see):

```tsx
const projects = useProjectStore((s) => s.projects)
const label = projects.find((x) => x.id === p.project_id)?.name
  ?? `${p.project_id.slice(0, 8)}...`
```
