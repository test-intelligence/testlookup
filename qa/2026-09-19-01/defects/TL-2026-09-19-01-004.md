# TL-2026-09-19-01-004 — Clustering that never ran is reported as "0 / no clusters"

- Found by: JR-04 step 3 (completeness)
- Severity: **S3** (a measurement that was never taken, displayed as a result) · Priority: P2
- Component: `frontend/src/pages/RunIntelligencePage.tsx` (`TestOutcomeCard`)
- Status: **FIXED** on `qa/jr04-ai-report-2026-09-19`

## Measured

Run `0613ab2f` — 10 tests, **2 failed**. The intelligence report returned:

```
failure_clusters      []
deep_pipeline_status  {"status": "never_run", ...}
pipeline_stages       ingestion, anomaly_detection, root_cause_analysis, summary, triage
```

and the card rendered:

```
Anomalies
0
no clusters
```

A run with two real failures states that zero anomalies and no clusters were
found. The plan's requirement for this step — "clusters cover all failures or an
explicit `N unclustered`" — is met by neither: `git grep unclustered` over the
whole repo returns **nothing**; the concept does not exist.

## Cause — not the cluster agent

`cluster_agent.py:40-55` returns `[]` only when there are no failed tests, and
logs `skip_no_failures` when it does. It never ran here. `failure_clustering` is
in `workflow.py: DEEP_REQUIRED_STAGES`, i.e. the **deep** workflow only, so an
`offline` pipeline has no clustering stage by construction — which
`pipeline_stages` confirms and `deep_pipeline_status: never_run` corroborates.

So `failure_clusters: []` is overloaded. It means either "clustering ran and
grouped nothing" or "clustering never ran", and the reader cannot tell which.
For every `offline` pipeline — the default — it always means the second.

The payload already carried the answer. `pipeline_stages` lists what actually
executed, and the page never consulted it; `deep_pipeline_status` was fetched and
had **zero** references in the page.

## Fix

`TestOutcomeCard` takes `clusteringRan`, derived from the stage list:

```tsx
clusteringRan={pipeline_stages.some((s) => s.stage_name === 'failure_clustering')}
```

- did not run → value `—`, caption "not run — deep investigation only"
- ran, nothing grouped → `0`, caption "no clusters found"
- ran, grouped → the count

Derived from the **stage list** rather than the workflow name deliberately: a
name check would silently break the moment clustering is added to another
workflow, while the stage list reports what a pipeline actually executed.

The stat is also relabelled **Clusters**. It read "Anomalies" while displaying a
cluster count; the intelligence payload exposes no anomaly count for the page to
use instead (the `anomaly_count` observed in this journey lives in
`agent_stage_results`, not in this response). Naming it for what it shows is
honest; giving the card a real anomaly count is a separate change and was not
attempted here.

Asserted over the page source, because the defect was a *string shown to a user*
and the fix is a branch on a prop — both visible in source, where mounting the
page would need the whole SWR/router/store stack for a two-line assertion.

- the old unconditional `'no clusters'` expression is gone
- "not run — deep investigation only" is present

- one real render, so the suite cannot become source-only without noticing

- First draft used `s.stage`; `tsc` rejected it — the payload and the

  getting it wrong makes `clusteringRan` permanently false and restores the
