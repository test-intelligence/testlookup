# TL-2026-09-18-01-002 — A leftover pytest scratch directory fails the mcp image build

- Reported by: ORCH, Phase 0 bootstrap (`make dev`)
- Confirmed by: independent direct `docker build` of the same context
- Severity: S2 (blocks the local stack; blocked this program's Gate B0)
- Priority: P1
- Component/surface: `mcp/.dockerignore`, `backend/.dockerignore`,
  `frontend/.dockerignore`
- Journey: n/a (environment / build)
- Status: **FIXED** — merged to `main` in PR #126 on 2026-09-19.
  (The "FIX READY" label below predates that merge and was never updated;
  corrected 2026-09-20 after verifying the change is present on `main`.)

## Reproduction

1. Run any pytest invocation that passes `--basetemp=<something>/.pytest_cache_t0`
   under the repo. pytest creates the directory owner-only on Windows.
2. `make dev` (or `docker build -f mcp/Dockerfile mcp/`).

Expected: the context walk skips pytest scratch directories, as all three
`.dockerignore` files intend.

Observed:

```
Error: building at STEP "COPY . .": ... copier: get: "/"("/"):
getting extended attributes for "/.pytest_cache_t0":
listing extended attributes of "/.pytest_cache_t0": permission denied
```

`make dev` fails earlier for the same reason on `backend/.pytest-cache-m10`:

```
checking context: can't stat
'\\?\C:\Users\anand\Downloads\Projects\testlookup_new\backend\.pytest-cache-m10'
```

## Evidence

- `make dev` → `MAKE_DEV_EXIT=2`.
- Direct `docker build -f mcp/Dockerfile -t testlookup-mcp mcp/` → exit 12,
  error above.
- 240 such directories exist in the working tree; the oldest is two weeks old.
  Several cannot be listed or even have their ACL read.

## Triage and review

The declared patterns were `.pytest_cache/`, `.pytest_tmp*/` and `.pytest-*/`.
`.pytest_cache_t0` is underscore-spelled but is a *cache*, not a *tmp*, so it
matches none of them:

| Pattern | Matches `.pytest_cache_t0`? |
|---|---|
| `.pytest_cache/` | no — exact name |
| `.pytest_tmp*/` | no — `tmp` vs `cache` |
| `.pytest-*/` | no — hyphen vs underscore |

The file's own comments record that each of those three patterns was added
*after* a build had already broken on the spelling it covers. This is the third
repetition of the same mistake: patch the instance, leave the class open.

**A hypothesis that was wrong and is recorded so nobody re-tests it:** all three
`.dockerignore` files are 100% CRLF, and podman echoes the parsed patterns with
a trailing carriage return (`"**/__pycache__/\r"`). That looks like it would
make every pattern inert. It does not. Tested on a synthetic two-variant context
— identical LF and CRLF `.dockerignore` files, each excluding
`**/__pycache__/` — and both images contained exactly `keep.txt`, no marker
file. Podman strips the carriage return. CRLF is not a defect here.

## Fix

Replaced the three narrow patterns in all three build contexts with one pattern
for the whole class:

```
.pytest*/
**/.pytest*/
```

The comment above them now names the failure mode (owner-only directories that
the context walk cannot stat) so the next reader does not add a fourth spelling.

The 240 leftover directories are NOT deleted by this fix. They are untracked
scratch from earlier sessions, several are permission-locked, and removing them
would need `takeown`. The build no longer cares about them — that is the point
of widening the pattern. Cleaning them up is a separate, owner-approved task.

## Tests added (MANDATORY — both)

- Unit: `scripts/test_quality_gate.py` — 4 tests for the new guard, including
  one that fails if the guard stops scanning the working tree.
- Gate / integration: new quality-gate guard
  `repo.dockerignore-covers-pytest-scratch` in `scripts/quality_gate.py`. It
  asserts behaviour, not pattern text: every pytest scratch spelling — a
  hard-coded list of the ones that have each broken a build, **plus every
  `.pytest*` directory currently on disk** — must be excluded by some declared
  pattern in every build context. Runs in CI via the `quality-gate` job.
  Documented in `architecture/DEVELOPER_GUIDE.md` as an absolute rule (no
  baseline: it ships at zero).

Asserting the literal strings `.pytest*/` and `**/.pytest*/` were present would
have re-made the original mistake one level up.
