## Reproduction

1. Read the route table in `frontend/src/App.tsx` (`appRoutes` + `managementRoutes`).
   The declared paths are `/failures`, `/test-management`, `/flaky-coach`.
2. Read the sweep targets:
   - `frontend/tests/probe-route-sweep.spec.ts` visits `/failure-analysis`
   - `frontend/tests/probe-exploratory.spec.ts` visits `/tests` labelled
     `'Test management'` and `/flaky` labelled `'Flaky coach'`
3. None of those three paths is declared. `App.tsx` ends with
   `<Route path="*" element={<Navigate to="/overview" replace />} />`, so each
   one resolves to the dashboard.
4. Live confirmation: sign in to `http://testlookup.local` as `admin`, navigate
   to `/failure-analysis`, and read `window.location.pathname` after routing
   settles.

Expected: `/failure-analysis` either renders the Failure Analysis page or is
absent from a sweep that claims to cover it.

Observed: final pathname is `/overview`.

## Triage and review

The sweeps assert that a page "is not an error boundary, not an empty shell,
and did not quietly fail an API call". `/overview` satisfies all three, so the
assertions pass and the suites report coverage for three pages they never
opened. This is the "a test can pass having done nothing" class: the failure is
invisible precisely because the app's catch-all redirect is working correctly.

No application defect. `App.tsx`'s catch-all is deliberate and the sidebar links
to the correct paths, so no user-facing navigation is broken.

Why existing tests missed it: nothing compares the route strings used by the
Playwright suites against the route table they are supposed to exercise. Each
list is maintained by hand, independently.

## Fix

Instance fix — corrected the three spellings:

| Spec | Was | Now |
|---|---|---|
| `probe-route-sweep.spec.ts` | `/failure-analysis` | `/failures` |
| `probe-exploratory.spec.ts` | `/tests` | `/test-management` |
| `probe-exploratory.spec.ts` | `/flaky` | `/flaky-coach` |

Class fix — `frontend/src/App.routeTargets.test.ts` parses `App.tsx`'s route
tables and every `probe-*.spec.ts`, and fails when a spec navigates to a path
the router does not declare. A literal ending in `/` is judged as an
interpolation prefix (`${BASE}/runs/${id}`), so real template usage passes while
a typo in the prefix still fails. `/api-docs` is allow-listed: it is served by
the backend, not the SPA router.

The class fix matters more than the instance fix. Correcting three strings does
not stop the fourth, because nothing else compares the two lists.
