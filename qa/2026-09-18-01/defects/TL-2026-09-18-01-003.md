# TL-2026-09-18-01-003 — The release KPI strip presents invented statistics as measurements

- Reported by: EX-03 (Interface tour — placeholder-as-fact scan)
- Confirmed by: source-level call-site analysis; every fabricated value traced
  to a literal in `KpiStrip.tsx` and to a call site that cannot override it
- Severity: S2 (fabricated data on a release-decision surface)
- Priority: P1
- Component/surface: `frontend/src/components/releases/KpiStrip.tsx`,
  rendered by `frontend/src/pages/ReleasesPage.tsx:847` at `/releases`
- Journey: JR-06 (Release gate) — adjacent surface
- Status: **FIXED** — merged to `main` in PR #126 on 2026-09-19.
  (The "FIX READY" label below predates that merge and was never updated;
  corrected 2026-09-20 after verifying the change is present on `main`.)

## Reproduction

1. Open `/releases` as QA_LEAD or ADMIN with any set of releases.
2. Read the four KPI cards above the filter bar.
3. Compare each card's trend line and caption against
   `frontend/src/components/releases/KpiStrip.tsx`.

Expected: a KPI strip states numbers it has counted.

Observed (before fix), at `KpiStrip.tsx:143-164`:

```ts
sparkline: [4, 5, 4, 6, 7, 6, 7, inProgress.length || 6],
sparkline: [1, 2, 1, 2, 3, 2, 2, readyToShip.length || 2],
sparkline: [0, 1, 1, 0, 1, 1, 1, blocked.length || 1],
sparkline: [8, 9, 10, 11, 11, 10, 11, last30Days || 11],
sub: 'avg gate <strong>97.1%</strong>',
sub: '<strong>100%</strong> audit-packed',
sub: 'from last week',
```

Seven of the eight points in every trend line are hardcoded literals. The
eighth is the only real value, and `|| N` replaces a genuine zero with an
invented constant *inside the series*, so a project with nothing in progress
still draws a line ending at 6. `avg gate 97.1%` and `100% audit-packed` are
stated as measurements and are computed from nothing at all.

## Evidence

- `ReleasesPage.tsx:847` renders `<KpiStrip releases={derived} />` with **no
  `override`**, and `KpiStrip` does `const cards = override ?? deriveKpis(releases)`.
  There is no code path in the product that avoids the fabrication.
- `MiniSparkline` labels itself `aria-label={`trend ending at ${last}`}`, so a
  screen-reader user is told a trend exists.
- Nothing supplies a time series to this component: `derived` is a release
  list, not history.
- `git grep` found no test referencing `KpiStrip`. The component had **zero**
  test coverage, which is why the literals survived.

## Triage and review

`OverviewPage` was fixed for this exact rule on 2026-08-16 — its regression is
named *"a KPI caption must not deny its own value"* and its comment records the
principle: a sparkline needs at least two real points, and the caption in the
sparkline's slot must explain the missing trend rather than assert a metric.
`KpiStrip` is the second module under the same rule and never received it.

Blast radius: display only. No API, persistence or authorization impact. The
large headline numbers on each card were always real — only the trend lines and
the captions were invented.

## Fix

Removed every fabricated value rather than deriving a fake series from one
point:

- All four `sparkline` literals deleted. A release list carries no history, so
  these cards draw no trend line. The `sparkline` prop and `MiniSparkline`
  remain for `override`, which is the only supported source of a real series.
- `avg gate 97.1%` and `100% audit-packed` deleted.
- `'from last week'` deleted — it described a week-over-week comparison the
  card does not make.
- `Ready to ship` now carries a caption it computes: `N of M in progress`.
- The genuinely-derived Planning caption is unchanged.

## Tests added (MANDATORY — both)

defect is: the `|| N` fallback never affected a displayed number. Every headline
count was real. The fabrication was the trend lines and the captions.
