# TL-2026-09-18-01-005 — Every ingested run carries a NULL duration

- Reported by: JR-01 (Ingestion journey), first hop
- Confirmed by: live re-ingest against the running stack, before and after fix
- Severity: S2 (a measured field is silently dropped; the product then blames
  the user's data for it)
- Priority: P1
- Component/surface: `backend/app/services/ingestion.py::_update_run_aggregates`,
  surfaced at `/runs` (`frontend/src/pages/RunsPage.tsx:363,1304`)
- Journey: JR-01 → JR-02
- Status: **FIXED** — merged to `main` in PR #126 on 2026-09-19.
  (The "FIX READY" label below predates that merge and was never updated;
  corrected 2026-09-20 after verifying the change is present on `main`.)

## Reproduction

1. `make dev`, then authenticate.
2. `POST /api/v1/ingest/file` with `samples/junit/auth-suite.xml`,
   any `project_id`, any `build_number`.
3. Poll `GET /api/v1/ingest/uploads/{task_id}` until `state: succeeded`.
4. `GET /api/v1/runs/{run_id}`.

Expected: `duration_ms` reflects the run. The sample declares its own:
`<testsuite name="AuthSuite" ... time="12.456">`, and its six cases carry
`time` attributes summing to exactly 12.456 s.

Observed: `duration_ms: null`.

## Evidence

Upload accepted and parsed correctly — the counts are right, so this is not a
parse failure:

```
upload  -> {"state":"succeeded","result":{"total":6,"attempted":6,"rejected":0,
            "complete":true,"passed":3,"failed":2,"skipped":1}}
run     -> total_tests=6 passed_tests=3 failed_tests=2 skipped_tests=1
           pass_rate=60.0 primary_suite_name=AuthSuite
           duration_ms=None            <-- here
```

The per-case durations are parsed and stored correctly:

```
FAILED  dur=2100  AuthSuite  test_login_expired_token
FAILED  dur=4120  AuthSuite  test_password_reset_flow
PASSED  dur=892   AuthSuite  test_login_invalid_password
PASSED  dur=1234  AuthSuite  test_login_success
PASSED  dur=3210  AuthSuite  test_register_new_user
SKIPPED dur=900   AuthSuite  test_oauth_google_redirect
                  ---------
                  sum 12456 = the suite's own declared time
```

`grep -rnE "(run|test_run|db_run|existing_run)\.duration_ms\s*=" backend/app/`
returns **nothing**. `TestRun.duration_ms` had no writer anywhere in the
application, on either ingest path.

Seeded runs do have durations (98716, 131178, 147489 …) because the seeder sets
the column directly. That is why this survived: the app's own demo data was
whole and only real uploads were not.

## Triage and review

`_update_run_aggregates` recomputes `total_tests`, `passed_tests`,
`failed_tests`, `skipped_tests`, `broken_tests`, `unknown_tests`, `pass_rate`,
`status` and the suite attribution. It was already issuing a `SELECT` that
aggregates over exactly the `TestCase` rows holding `duration_ms`. It just never
summed them.

**The user-visible consequence is worse than a blank cell.** `RunsPage`
computes metadata coverage as

```ts
const withMeta = runs.filter(r => !!r.branch && !!r.release_name && (r.duration_ms ?? 0) > 0).length
const hasMissingMetadata = totalRuns > 0 && metadataCoveragePct < 80
```

so every uploaded run fails that check on a field the product declined to
compute, and the page tells the user their CI data is incomplete.

Why existing tests missed it: the two existing `_update_run_aggregates` tests
assert counts and fingerprints, never duration, and the seeded fixtures carry
durations from elsewhere.

## Fix

`_update_run_aggregates` now adds `func.sum(TestCase.duration_ms)` to the
aggregate it already runs, and writes it to the run.

Semantics — the sum of case durations, not run wall-clock. That is the figure
the source file itself reports (`AuthSuite` declares `time="12.456"` and its
cases sum to 12456 ms). The run's `start_time`/`end_time` span the ingest
request (0.43 s here), which is not the test execution and would be a second
fabricated number.

`NULL` is preserved when no case carried a duration. A run nobody timed has not
been measured at 0 ms.

## Verification evidence

- Red before fix, live: run `2f1afd7a` → `duration_ms = None`.
- Green after fix, live: run `7e63ba21`, same file → `duration_ms = 12456`,
  matching the suite's self-declared `time="12.456"`. Counts unchanged
  (6 / 3 / 2 / 1, pass_rate 60.0, suite AuthSuite).
- Mutation — write `0` instead of the sum (what "just populate the column"
  looks like): **all 4 tests fail**, including
  `test_an_unmeasured_run_stays_null_rather_than_zero`, which is the one that
  distinguishes "not measured" from "measured as zero".
- `ruff check app/ tests/` → clean. `scripts/quality_gate.py` → 44 guards passed.

## The fix broke three existing tests, and CI is what found it

Adding `func.sum(TestCase.duration_ms).label("duration_ms")` to the select made
the handler read `counts.duration_ms`. Three regression tests build that result
row by hand as a `SimpleNamespace`, and a hand-built row does not grow a new
column:

```
AttributeError: 'types.SimpleNamespace' object has no attribute 'duration_ms'
  tests/regression/test_ingestion_savepoint_isolation.py::test_incomplete_run_aggregate_status_is_stopped
  tests/regression/test_pass_rate_excludes_skipped.py::test_pass_rate_excludes_skipped_from_denominator
  tests/regression/test_pass_rate_excludes_skipped.py::test_pass_rate_is_100_when_all_executed_pass_despite_skips
```

The precedent was written in the file already — *"``unknown`` added when
test_runs gained an unknown_tests column (0118) — the fixture is extended, not
the assertion weakened."* The same move applies here; I did not grep for it.

Fixed in `ec263277` by extending the three fixtures **and** asserting the summed
duration reaches the UPDATE, so the fixture edit carries coverage instead of
only silencing the error. `grep -rln _update_run_aggregates tests/` returns ten
modules; all ten were run together — **100 passed**, and only three needed the
change.

Mutation: dropping `"duration_ms"` from `values_to_update` — the original
defect's exact shape, summed but never assigned — fails both new assertions.

### Why the baseline did not catch it

The Gate B0 backend run (24 failed / 11,946 passed) was measured **before**
`ingestion.py` was edited, and was never re-run after. A baseline taken before
the change cannot see the change. The affected suite has to be re-run after the
last source edit, not before it.
