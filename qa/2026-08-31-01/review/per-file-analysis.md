# Pass 1 — Per-file analysis

## Backend and frontend regression surfaces

- `frontend/src/pages/DocsPage.test.tsx`: the full frontend suite exposed a fake-timer/React flush timeout in the copy-control regression. The test now advances timers asynchronously inside `act`; the full suite and coverage run pass.
- `backend/app/services/connectors/document_connector.py`: mixed DOCX blocks were collected as all paragraphs followed by all tables, changing source order before chunking. The extractor now walks the document body and preserves paragraph/table order, with a real in-memory DOCX regression.
- `backend/app/services/report_html_renderer.py` and `backend/app/services/notification/email_templates.py`: persisted status/release/provenance labels were displayed without HTML escaping. The renderers now escape displayed untrusted labels; malicious-value tests cover report and email paths.
- `scripts/gen-dev-env.sh`: the local setup script hard-coded `python3`, which failed on Windows Git Bash where only `python.exe`/the active interpreter was available. Runtime selection now supports `python3`, `python`, `python.exe`, `py.exe -3`, and an explicit `TL_PYTHON_BIN` override.
- `backend/tests/test_release_artifacts.py`, deployment regression tests, and quickstart tests: shell discovery and child environments were not portable on Windows. Native Git Bash is preferred and Git POSIX utility directories are supplied to shell subprocesses.
- `backend/app/services/rag_staleness_service.py`: behavior was implemented but only model-field tests existed. Hash-change propagation, idempotence, and batch citation marking now have behavior-level tests.
- `backend/app/services/prompt_registry.py`: `_attest` replaces the repository's prompt eval-gate record but had no direct behavior tests. Offline success and both pre-write failure boundaries are now pinned.
- `backend/app/tools/fetch_app_metrics.py`: valid but non-object JSON, malformed windows, and non-string timestamps could raise out of the agent tool; naive UTC timestamps used host-local time and service names were interpolated into PromQL unescaped. Inputs are now validated/bounded and label/timestamp handling is deterministic.
- `backend/app/core/tracing.py`: tracing setup runs unguarded during `app.main` import, so exporter/resource/provider configuration errors could prevent the API from starting. Setup now fails open with a diagnostic, and already signal-qualified OTLP HTTP endpoints are not suffixed twice.
- `backend/app/services/webhook_service.py`: the schema and UI allow `max_retries=0`, but delivery used `max_retries or 5`, silently turning the explicit zero into five attempts. Retry-budget checks now distinguish zero from an absent legacy value and preserve immediate `FAILED` handling for non-retryable 4xx responses.
- `backend/app/services/webhook_service.py`: `emit_event` documented a never-raise, best-effort contract but its session/query/flush/commit path could escape exceptions. Persistence preparation now fails closed to zero with structured diagnostics and no payload logging.
- `backend/app/services/webhook_service.py`: all committed delivery enqueues shared one exception boundary, so the first broker rejection skipped every later subscription. Enqueue errors are now isolated and diagnosed per delivery while fan-out continues.
- `backend/app/worker/tasks.py`: unhandled `deliver` failures were converted to `retry=False`, causing Celery to acknowledge transient database/secret/setup faults while the committed delivery remained `PENDING`. They now use the task's existing bounded retry policy.
- `backend/app/services/webhook_service.py`: when `has_secret` was true but the secret was missing or undecryptable, delivery silently omitted the signature and posted anyway. Configured signing now fails closed before egress and records a terminal failure.
- `backend/app/services/webhook_service.py` and `backend/app/routers/webhooks_outbound.py`: replay enqueue failure left a taskless `PENDING` row and still returned success. The row is now marked `FAILED`, the service returns failure, and the API's 503 explains queue failure as well as gating.
- `backend/app/routers/integration_health.py`: on-demand Slack/Teams probes bypassed encrypted runtime webhook resolution and used process settings, unlike scheduled probes and actual delivery. The endpoint now resolves database-authoritative configuration through its request session.
- `backend/app/services/integration_probe_service.py`: encrypted Slack/Teams configuration loaded before the fault-isolated gather, so a database error prevented every unrelated probe from running. Configuration failure now becomes `down` for those providers while sibling probes continue.
- `backend/app/routers/integration_health.py`: an unknown `provider` query value fell through to the all-provider branch, turning a typo into broad external probing and unrelated persistence. Unknown providers now return 422 before side effects.
- `backend/app/services/integration_probe_service.py`: Prometheus gauge updates and removals occurred before the database commit, so a rejected transaction could leave dashboards ahead of and inconsistent with the status API. Metric changes are now staged and published only after persistence succeeds.
- `backend/app/routers/test_management_exports.py`: the strategy PDF used `_pdf_text`, but the plan PDF sent its name, status, description, and objective directly to ReportLab's markup parser. Malformed stored text reproducibly raised `ValueError`; all plan paragraphs now share the established escaping boundary.
- `backend/app/services/report_pdf_renderer.py`: executive status signals, baseline classifications, and provenance sources reached ReportLab `Paragraph` without escaping and each reproduced a parser failure. Its `_safe` helper also escaped before truncating, which could split `&lt;` into a bare ampersand; metadata is now escaped consistently and truncation preserves complete entities.
- `backend/app/routers/test_management_exports.py`: the XLSX writer passed persisted test-case text directly to openpyxl, which serialized a leading `=` as a formula cell. All exported text now crosses a formula-neutralization helper, with workbook-level assertions for title, feature area, objective, preconditions, expected result, and tags.
- `backend/app/services/audit_dashboard_service.py`: audit CSV rows were assembled by comma interpolation, so actor names containing commas/newlines changed columns and record count; formula-looking values also remained active. The standard CSV writer now owns quoting and a cell helper neutralizes spreadsheet formulas.
