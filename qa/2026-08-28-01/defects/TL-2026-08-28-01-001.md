# TL-2026-08-28-01-001 — Slack probe ignored DB webhook

- Reported by: FT baseline probe; confirmed by TR
- Severity: S3
- Component/surface: `backend/app/services/integration_probe_service.py`, integration health API
- Status: FIXED LOCALLY; pending independent review, homelab deployment, and verification

## Reproduction

1. Provide `probe_slack` with `slack_enabled=true` and a DB-resolved `slack_webhook_url`.
2. Leave the environment bot-token setting populated with its placeholder value.
3. Observe the result.

Expected: `healthy`, because webhook configuration is the runtime DB authority.
Observed before fix: `auth_error`, because the probe attempted Slack bot-token authentication first.

## Root cause and fix

`probe_slack` checked `settings.SLACK_BOT_TOKEN` before the caller-supplied runtime webhook. The fix makes a non-empty runtime webhook authoritative, then falls back to bot-token probing only when no webhook is configured.

## Evidence

- Before fix: `test_global_webhook_runtime_authority.py::test_health_probes_use_db_global_webhooks` failed (`auth_error` vs `healthy`).
- After fix: the full regression file passed, 6 tests.
- Ruff passed for the touched module.
