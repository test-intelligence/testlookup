# TL-2026-08-28-01-002 — Public URL fallback ignored explicit CORS input

- Reported by: FT baseline probe; confirmed by TR
- Severity: S3
- Component/surface: `backend/app/core/config.py`, share links and notification URLs
- Status: FIXED LOCALLY; pending independent review, homelab deployment, and verification

## Reproduction

1. Construct `Settings(PUBLIC_BASE_URL="", CORS_ORIGINS_RAW="http://testlookup.local")`.
2. Read `settings.public_base_url`.

Expected: `http://testlookup.local`, the first supplied CORS origin.
Observed before fix: `http://localhost:3000`, because the dotenv alias `CORS_ORIGINS` replaced the explicitly supplied field-name value.

## Root cause and fix

`CORS_ORIGINS_RAW` used `alias="CORS_ORIGINS"`. In `pydantic-settings`, the alias source could override an explicit field-name constructor value. The field now uses `validation_alias=AliasChoices("CORS_ORIGINS_RAW", "CORS_ORIGINS")`, retaining the environment variable contract while preserving explicit field-name precedence.

## Evidence

- Before fix: `test_share_link_uses_public_base_url.py::TestTheResolverItself::test_it_falls_back_to_the_first_cors_origin` failed (`localhost:3000` vs `testlookup.local`).
- After fix: the full regression file passed, 6 tests.
- Ruff and all 30 quality gates passed.
