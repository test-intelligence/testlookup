# infra/aws — TestLookup on AWS (EKS + managed data)

Terraform IaC + scripts to run TestLookup on AWS, plus an **offline quality gate**
that validates everything **without a real AWS account**.

Full design: [STRATEGY.md](./STRATEGY.md). Original Q&A: [deployment_instructions.md](./deployment_instructions.md).

```
infra/aws/
├── STRATEGY.md                  deployment strategy + architecture
├── terraform/
│   ├── versions.tf providers.tf variables.tf main.tf outputs.tf backend.tf
│   ├── terraform.tfvars.example
│   ├── environments/{dev,staging,prod}.tfvars
│   └── modules/{network,ecr,eks,data}/
└── scripts/
    ├── validate.sh              offline quality gate (no AWS)   ← start here
    ├── bootstrap-state.sh       one-time: S3 state bucket + DynamoDB lock
    ├── plan.sh                  read-only change review (needs creds)
    └── deploy.sh                gated apply (needs creds; prod = typed confirm)
```

## Validate without AWS (the quality gate)

```bash
# Runs terraform fmt/validate, tflint, tfsec, kustomize render, hadolint, shellcheck.
# Each tool is used from PATH or its Docker image; missing ones are skipped.
./infra/aws/scripts/validate.sh

# Dev hosts with a TLS-inspecting AV (Norton/NordVPN) that breaks terraform's
# loopback plugin mTLS — run terraform inside a container instead:
./infra/aws/scripts/validate.sh --tf-docker
```

CI runs the same gate on Linux: `.github/workflows/aws-infra-validate.yml`
(triggered by PRs touching `infra/aws/**` or the `aws-eks` overlay). No AWS
credentials are configured in that workflow.

Minimal manual checks:

```bash
cd infra/aws/terraform
terraform fmt -check -recursive
terraform init -backend=false      # resolves providers, touches no AWS/state
terraform validate
```

## Provision (when you DO have an account)

```bash
# 0. credentials (profile or OIDC role) with admin-ish create perms
export AWS_PROFILE=tl-dev AWS_REGION=us-east-1

# 1. one-time remote-state backend
./infra/aws/scripts/bootstrap-state.sh
export TF_STATE_BUCKET=testlookup-tfstate-<acct-id> TF_LOCK_TABLE=testlookup-tflock

# 2. review (read-only) then apply (gated)
./infra/aws/scripts/plan.sh   dev
./infra/aws/scripts/deploy.sh dev --confirm

# 3. point kubectl at the cluster, then deploy the app overlay
aws eks update-kubeconfig --region us-east-1 --name testlookup-dev
# (sync Secrets Manager → testlookup-secrets, set ECR image refs + ACM ARN, then)
kubectl apply -k k8s/overlays/aws-eks
```

## Guard rails

- `deploy.sh` refuses to run without `--confirm`; **prod** also requires typing `prod`.
- `allowed_account_ids` (per-env tfvars) can hard-block applies into the wrong account.
- All credentials are generated by Terraform and stored only in Secrets Manager —
  never in tfvars or git. RDS/DocumentDB have deletion protection.
