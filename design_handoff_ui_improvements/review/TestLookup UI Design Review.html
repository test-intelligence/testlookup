01

What's genuinely good

Credit first — the bones are strong, and several decisions are better than most production dashboards:

✓Semantic token architecture. Complete per-theme blocks (--status-*, --gate-*, --cat-*) with a registry-driven picker. Adding a theme is 2 edits.
✓Centered 1600px content column with responsive gutters, applied once in AppLayout — consistent across all routes.
✓PageHeader adopted by ~37 pages. Title/subtitle/actions are uniform nearly everywhere.
✓Grouped sidebar IA (Dashboard / Testing / AI Reports / Management) with permission gating, feature-flag gating, and a personal "My Failures" inbox with live count.
✓Thoughtful micro-engineering: stable callbacks, primitive Zustand selectors, scoped SWR polling — the discipline shows in comments like P4-1/P4-2.
✓Verdict-first dashboards. Overview and Runs lead with a release-readiness verdict band instead of a wall of numbers — the right hierarchy for the product.
02

Critical — undermines the theme system

3 findings
S1

201 hard-coded palette colors bypass the tokens

theming

The token layer is excellent — but the pages don't use it. A repo scan finds 201 matches of raw Tailwind palette classes (text-emerald-400, bg-red-900/40, text-amber-300…) plus dozens of literal hexes (#86efac, #fca5a5, #facc15) in verdict maps. Two consequences:

  • Light theme breaks. text-emerald-300 on Lab's paper background is ~2:1 contrast — illegible. Every one of these 201 spots is a light-theme defect.
  • Theme identity dilutes. Signal's warmed status palette (#7ce0a0/#ff8a6b) coexists with raw emerald/red — same screen, two greens, two reds.
// index.css defines the tokens… --status-passed: #7ce0a0; --status-failed: #ff8a6b; // …then ignores them 60 lines later in the SAME FILE: .badge-passed { @apply bg-emerald-900/50 text-emerald-300 border-emerald-700/60; } // should be: .badge-passed { color: var(--status-passed); background: var(--status-passed-bg); … }
FixThree moves: (1) rewrite the five .badge-* classes onto --status-* tokens; (2) codemod text-emerald-400 → text-[var(--status-passed)] etc. across pages; (3) add an ESLint rule (no-restricted-syntax on palette classnames) so it can't regress. The 201 hits are ~15 recurring patterns — a day of mechanical work.
S1

StatusBadge exists but only 2 pages use it

components

Pass/fail/skip status is the single most repeated visual in the product, and it's re-implemented per page: AgentStatusPage, CanonicalDetailPage, FlakyCoachPage, LiveExecutionPage, IntelligenceHubPage… each defines its own STATUS_COLORS map with slightly different hues, casing, and paddings. Meanwhile the shared StatusBadge component has exactly two importers.

Users see the drift: "PASSED" is a pill on one page, colored text on another, a dot on a third; skipped is amber here and gold there; some pages use green-400, others emerald-400.

FixMake StatusBadge the only way to render a test status: variants pill / text / dot, sizes sm / md, driven entirely by --status-*. Delete the per-page maps as each page migrates. Same treatment for a GateBadge (it already exists under components/releases — promote it).
S1

Profile menu is hover-only — keyboard & touch users can't sign out

accessibility

UserProfileDropdown opens via opacity-0 group-hover:opacity-100 on a cursor-pointer div. There is no click handler, no aria-expanded, no focus trigger — on a tablet or by keyboard, Sign out is unreachable. The bell dropdown right next to it does this correctly (click + outside-close + aria).

FixMirror the bell's pattern: <button aria-haspopup="menu" aria-expanded>, click-to-toggle, Esc + outside-click to close, focus moves into the menu. ~30 lines; reuse the hook.
03

High — visible quality & UX gaps

7 findings
S2

Verdict bands are half-tokenized — WATCH invents a 6th color family

theming · color

OverviewPage and RunsPage each carry a private VERDICT_THEME mixing tokens (var(--gate-go)) with raw hexes (#86efac, #fcd34d, #facc15). The WATCH state adds a lemon-yellow family distinct from CONDITIONAL's amber — a distinction that's nearly invisible in practice and gone entirely for deutan/protan users:

WATCH #facc15 CONDITIONAL #ffb347 ← can you tell at a glance?

The two files also disagree — same verdict, different hex per page.

FixAdd --gate-watch (+bg/bd) per theme; extract one shared <VerdictBand>; differentiate WATCH from CONDITIONAL by shape/label, not hue alone (e.g. outline pill + "eye" icon vs filled pill + "alert" icon).
S2

Micro-typography below the legibility floor

type

Dozens of text-[10px] and text-[9px] labels (sidebar mode badge, notification meta, pill counts, table chips). At 9–10px, Plus Jakarta Sans loses its counters at typical zoom; on 1440p monitors these are ~7 physical px. The floor for functional UI text should be 11px, with mono eyebrows at 10.5px minimum.

FixSweep text-[9px]|text-[10px] → text-[11px]; where space is tight, drop the label and keep the icon with a tooltip instead of shrinking text.
S2

Every MetricCard is a polite live region

accessibility

MetricCard renders role="status" aria-live="polite" unconditionally. A dashboard with 6–8 cards re-announces every value on every refetch — for screen-reader users, the Overview page narrates itself continuously while SWR polls.

FixRemove the live region from the card. Announce one summary ("Dashboard updated") from a single visually-hidden region per page, or only announce genuine state transitions (verdict change).
S2

Trend color assumes up = good

data-viz

MetricCard colors trend_direction==='up' green and 'down' red — but for Failed tests, Flaky count, or Duration, up is bad. Unless every caller pre-inverts the direction (they don't), the card congratulates rising failure counts.

FixAdd positiveDirection: 'up' | 'down' to the card (default 'up'); color by trend_direction === positiveDirection. Callers for failure/duration metrics pass 'down'.
S2

Project switcher is a native <select> beside two custom dropdowns

consistency

The TopBar has three adjacent popovers: a custom notification panel, the custom ThemePicker, and a bare native <select> for the most important context switch in the app (project). The native control ignores the theme (OS-rendered menu), truncates long names, can't show project metadata, and visually clashes with its neighbors.

FixRebuild as a ThemePicker-style popover: search field for many projects, "All Projects" pinned for admins, active-project check, and the project's pass-rate dot as a glanceable health cue.
S2

Sidebar semantics: action-as-nav, icon mismatches, split hit-target

navigation
  • "Upload Report" is an action, not a place — it lives in nav as /runs?upload=1. Clicking it navigates and opens a modal; the nav item never shows as active. It belongs as a button on the Runs page (or a global "+" in the TopBar).
  • Icon semantics drift: Defects = Gauge (a speedometer?), and four near-identical shields (Shield, ShieldAlert, ShieldCheck, ShieldEllipsis) across Coverage / Quarantine / Release Gate / Policies make scanning by icon useless.
  • Split hit-target: the group row navigates while a separate 24px chevron toggles expansion — users learn this by mis-clicking. Standard pattern: row click toggles when the group is already active, navigates otherwise (or make the whole row toggle + a "view" affordance).
FixMove Upload to a page-level primary button; re-icon Defects (Bug is taken — use ClipboardX/OctagonAlert) and diversify the shield cluster; unify the group row interaction.
S2

Search is Enter-only — no ⌘K, no palette, no scoping

ux · power users

For a data-dense engineering tool, search is a single TopBar input whose placeholder literally teaches the crutch: "Search tests, runs, defects… (Enter)". No keyboard shortcut, no typeahead, no recent items, no entity scoping — yet the backend already supports hybrid/semantic search modes on /search.

FixPromote to a ⌘K command palette: recent runs, jump-to-page, entity-scoped queries (run:, test:, defect:), and actions ("Compare last two runs"). The existing SearchPage becomes the "see all results" surface. This is the single highest-leverage UX upgrade available.
04

Medium — polish & hygiene

4 findings
S3

Monolithic pages breed the drift

architecture

RunsPage 2,211 · OverviewPage 1,207 · IntelligenceHubPage 946 lines. Every finding above (private verdict maps, private status colors) lives inside these monoliths — inconsistency is the natural byproduct when shared visuals are page-local constants. The components/releases/ folder shows the team already knows the cure.

FixExtract the repeated organisms: VerdictBand, RunListRow, PassRateMeter, TrendDelta. Rule of thumb: any visual that appears on 2+ pages moves to components/.
S3

Timestamps are raw locale dumps

content

Notifications render new Date(log.created_at).toLocaleString() → "7/2/2026, 4:08:13 PM" in a 320px panel. The codebase already has dayTimeAgo in utils/formatters.

FixRelative time ("4m ago") with absolute on hover/title, everywhere a human scans a list.
S3

Aurora uses background-attachment: fixed

performance

background-attachment: fixed disables composited scrolling in Chromium — every scroll repaints the gradient. On the 2,000-row Live table this is measurable jank.

FixPaint the aurora on a position: fixed; inset: 0; z-index: -1; pointer-events: none div instead — same look, zero scroll cost.
S3

Clickable rows without keyboard equivalence

accessibility

.table-row is cursor-pointer with an onClick — a div-click pattern. No tabindex, no Enter/Space activation, no row link semantics. Keyboard users can't open a run from the Runs table.

FixMake the row's primary cell a real <Link> (stretched-link pattern), or add tabindex=0 + key handlers. Real links also restore middle-click / cmd-click — power users will thank you.
05

Bigger UX bets

beyond fixes

The pages are individually strong; what's missing is connective tissue — the app behaves like 40 destinations rather than one investigation flow. Three bets, in value order:

BetWhat it isWhy it wins
⌘K command palette Global jump + search + actions (covered in S2). Recent entities first; scoped prefixes; "Compare", "Quarantine", "Open gate" as verbs. daily-use speed for every persona
Investigation thread A failure's journey spans Runs → Failure Analysis → Deep Investigate → Defects → Release Gate, but each hop loses context. Add a persistent "thread" ribbon (breadcrumb + carried filters + back-to-run) so drilling into a failure and returning doesn't reset state. kills the #1 dead-end pattern
Density toggle Tables are one-size (py-3). QA leads triaging 500 failures want compact (py-1.5, 12px); execs want comfortable. One control in the TopBar, one CSS var (--row-pad). cheap; huge for heavy users
